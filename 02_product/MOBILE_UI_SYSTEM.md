# 观微移动端视觉规范 1.0

状态：2026-09-07，用户确认采用「清爽浅色＋低饱和绿」。对应 v0.15 和 MADR-036。范围：Android 键盘、安装与连接、建议/图片/候选；iPhone 主 App 与建议扩展。

## 视觉方向与配色

气质：清楚、安静、易读。浅色页面、白色输入区、深色文字，绿色集中表达主要动作。保留系统字体和平台交互，不引入装饰插画、渐变、玻璃效果或皮肤库。

| 语义 | 色值 | 用途 |
|---|---|---|
| 页面 | `#F5F7F6` | 页面背景 |
| 表面 | `#FFFFFF` | 输入框、候选、普通按键 |
| 正文 | `#202B27` | 标题、输入文字、键帽 |
| 次级文字 | `#58665F` | 提示、状态、说明 |
| 主要操作 | `#27634D` | 分析、批准、确认插入、焦点描边 |
| 浅绿 | `#E6EFE9` | 辅助操作背景 |
| 边框 | `#C3CEC7` | 区分输入区域 |
| 键盘底 | `#E8EDE9` | 键盘容器与导航栏 |
| 功能键 | `#D6E1D9` | 切换、退格、换行等 |
| 系统导航区域 | `#7C847F` | 兼容宿主决定的黑/白导航图标；只绘制实际导航 inset |

配比目标：约 **70% 中性背景 / 25% 白色内容表面 / 5% 绿色强调**。这是控制视觉权重的设计目标，不是对所有页面的像素计量或通用科学定律；键盘因白色键帽可例外。不可为了凑比例给无关区域涂绿。

正文与背景、绿色按钮与白字须达到 WCAG AA 普通文字 4.5:1；次级文字同样检查，禁用态用文字、可点击状态一起表达。边界辅助识别，输入提示/标签仍须保留，错误不可只变红。对比度计算归档到 `output/ui-v015/contrast.json`。

## 尺度与布局

- 使用系统字体；Android 标题 28sp、分区 18sp、正文/输入 15–16sp、辅助 12–14sp、键帽 18sp。iOS 使用 Dynamic Type 的 title3/headline/body/subheadline，避免固定像素字号。
- 页面左右 20dp，组件间距 8dp，分区间距 24dp。圆角：按键 8dp、输入/按钮 12dp；平面为主，去除 Android 原生按钮默认悬浮阴影。
- Android 普通操作至少 48dp 高，输入至少 52dp 高；iOS 操作至少 44pt、扩展操作 48pt。文字可换行，人物确认按钮不得省略人物。
- 十列键盘在窄手机上无法每键都达到 48dp 宽，作为高密度键盘例外记录；纵向触摸区 52dp（横屏 48dp），2dp 横向/3dp 纵向视觉内缩包含在完整触摸区内。第二字母行左右缩进 14dp，保留熟悉的 QWERTY 排列。
- 键盘常态：状态与「建议」并列、候选栏、字母区、功能行；有草稿时人物确认按钮展开全宽并允许换行。候选翻页触摸区 48dp；密码等私密输入无建议入口。
- 建议页固定分区：设备连接 → 01 核对人物与目标 → 02 准备聊天片段 → 03 审阅与编辑候选。先看清当前对象与原话，再批准分析，再审阅/插入。
- 使用平台滚动、系统栏和键盘避让；长文案不强行限制一行。Android 保留 FLAG_SECURE，建议页视觉验证以控件树、可达性和交互回归为证，不关闭保护获取普通截图。
- iPhone 建议扩展把草稿放在 120pt 高的可滚动预览中，长草稿不把确认、刷新和输入法切换推出视图；完整文字仍能滚动查看，随系统字号变化。

## 状态与交互

| 状态 | 展示与动作 |
|---|---|
| 未连接/空候选 | 明确下一步，不能出现假的候选 |
| 请求中 | 保留「正在…」文字；iOS 展示进度指示，禁用对应请求按钮 |
| 已批准/可插入 | 绿色主操作，完整显示人物确认文案 |
| 失效/失败/离线 | 可读原因；旧候选不可插入；重新分析需再次批准 |
| 修改片段/人物 | 清除旧批准和结果，外观变化不能绕过授权 |
| 图片预览 | 展示待批准图片；批准转写与丢弃分清主次；回填后重新批准文字 |
| 插入完成 | 明示已插入草稿，发送仍由本人执行 |

保留语义标签、原测试 ID 与触摸目标。字体放大、旋转、短屏滚动、候选分页、私密输入、输入法切换、批准与失效逻辑均属于回归范围。

## 参考与实现

设计原则参考入口：[Material 3 颜色](https://m3.material.io/styles/color/overview)、[Material 3 字体](https://m3.material.io/styles/typography/overview)、[Apple HIG](https://developer.apple.com/design/human-interface-guidelines/)、[WCAG 对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。借鉴颜色角色、信息层级、平台控件与可读性；不宣称已通过这些规范的全面认证。

Android 集中在 `native/android/java/com/conversationlens/ime/LensStyle.java`；iOS 集中在 `native/ios/Shared/LensTheme.swift`。采用自有配色与原生控件，没有复制其他输入法前端，也没有新增 UI 第三方依赖。

## 固定规则，减少返工

本轮锁定浅色主题、配色、字号层级、间距、圆角和分区；暂不扩展换肤/深色主题。后续只在有证据的问题上修改：文字裁切、误触、对比不足、无障碍/平台兼容问题或明确需求变化。调整共享 token 后同时检查双端，记录原因与前后证据；不要每页自行选新颜色和尺寸。

视觉 DoD：实际 Android 键盘截图人工检查；语义树确认长按钮可达；原有键盘/插入/稳定性/选图回归；云端 Android API34/36 与 iOS 构建/UI 回归。模拟器通过不等于三聊天平台真机、VoiceOver/TalkBack 全面验收或生产发布。
