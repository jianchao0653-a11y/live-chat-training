# Android首版：按正常APP交付

2026-09-08，用户要求参照正常APP开发流程，避免把服务端和联调步骤转嫁给使用者。

用户已正式接受开发、连接、交付、迁移四项，决策见 [MADR-041](../03_decisions/MADR-041.md)，以该决策为当前执行依据。

## 用户可见流程

接收一个正式签名APK → 安装 → 一次性登录 → 系统启用并选择输入法 → 选择人物、主动提供聊天片段 → 获得可编辑建议 → 本人确认插入并决定发送。

输入法的系统启用是Android必要操作；Tailscale、USB调试、填写服务地址、API Key、命令行不属于首版用户流程。人物/关系/记忆/反馈管理放在APP现有界面。沿用既定UI，不重做视觉。

## 开发与交付顺序

1. 本机开发：当前电脑运行后端，使用独立数据目录；自动化验证账号隔离、资料维护、费用限制、生成和确认插入。当前58项Node测试通过，手机测试证据依旧按版本区分。
2. 发布准备：开发者配置手机可达的稳定HTTPS业务地址与受保护模型密钥；如继续用电脑当服务器，需要由部署端提供稳定公网入口，电脑保持开机联网。手机不安装联网辅助软件。尚未选定或开通稳定公网入口，不将临时随机地址视为正式交付。
3. 构建测试包：使用实际地址和既有独立生产签名打包，核验签名、密钥不在包内，并在小米Wi-Fi和手机流量上验证首次登录、第一条建议、断线提示及更新。
4. 小范围试用：先确认回复可用性，再执行既定人工评审和连续试用；开发者记录问题并交付同签名更新包，不让使用者配置开发工具。
5. 迁移：保留数据库结构和API协议。停止旧端写入后安全迁移完整最新数据及身份/费用/删除账本；能保留同业务域名则切换后端。如地址改变，当前实现仍需同签名APK更新与重新登录，不声称已具备无感切换能力。

## 当前收敛

- 电脑服务保留，作为开发/临时部署基础；已实现的一键正常启停继续可用。
- 暂停Tailscale私人网络交付路线，不再要求用户或后续试用者登录它。已安装的Windows客户端尚未登录，也未启用Serve/Funnel；不作额外系统变更。
- 不同时推进Render、阿里云、私人VPN三条部署路线，不购买未确认资源。
- 发布前仍须解决稳定HTTPS入口与模型预算，但属于开发部署工作，不能假装普通APP不需要后台运行成本。
- 当前没有可直接离家联网的正式APK；服务端自动测试通过不等于手机交付已经完成。
