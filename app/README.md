# 观微 · Conversation Lens 本地测试版

版本：0.14.0。适合项目发起人与授权测试者先跑业务流程；Android 与 iOS 均有原生工程预览，双端产品尚未完成相关真机和真实模型验收。

原生续作：[双端说明](../native/README.md)、[v0.14 验收](../07_reviews/V0_14_ACCEPTANCE.md) 与 [iOS 工程](../native/ios/README.md)。电脑“设置与数据”可生成限定当前主播的配对码、查看和撤销手机连接。iPhone 建议键盘使用 30 秒单次可撤销授权，主 App 的长期设备令牌不共享给键盘；当前没有签名 IPA。

## 启动

需要 Node.js 24 或更新版。在项目根目录双击 `启动测试版.cmd`，或执行：

```powershell
npm.cmd start
```

打开 http://localhost:4317 。无需 `npm install`。关闭命令窗口或按 Ctrl+C 停止服务，SQLite 中的记录会保留。

## 第一轮体验

顶部选择当前主播，到“设置与数据”登记花名、语气、常用语、Unicode 表情和输入习惯。六个初始位置只有占位名，没有虚构主播画像；人物编号和主播编号是不同命名空间。切到另一主播时，同一人物须点击“编辑档案”建立独立关系，不继承另一主播私聊。

1. 点“试试示例”，建立合成人物 `0001` 并填入对话；
2. 点“分析并生成建议”，查看情境、策略和三个表达候选；
3. 点候选，编辑自己的草稿，然后复制；
4. 展开“查看依据与 6+2 审核详情”；
5. 在“记录这次对话的后续”中保存观察结果；
6. 到“人物与关系”添加有来源的记忆，确认或争议信念；
7. 到“分析与复盘”重开记录；可导出 JSON 或删除人物及关联数据。

“林间 · 示例”是合成档案。人物编号与既有 `0001–0006` 参与者编号属于不同命名空间：UI 中编号是人物数据库 ID，不能据此推断参与者身份。

## 模型连接

在“设置与数据”填写 OpenAI API Key 和可用模型名称。默认模型名称来自当日官方示例，可自行改为账户支持结构化输出的模型。设置只保存在服务内存，API Key 不写入数据库、不回传浏览器、不进入导出。

也可用环境变量 `OPENAI_API_KEY`、`OPENAI_MODEL` 启动。密钥不要写进仓库文件或聊天记录。

一次模型分析先生成六领域意见、首席策略和候选，再单独请求终审。若终审拒绝、证据不是原文、角色缺失或接口出错，本次不输出未审候选。不会把云端错误静默降级为规则结果。

截图转写支持小于 4 MB 的 PNG/JPEG/WebP：选择图片后发送到配置模型，转写文本回到编辑框；先核对再分析。截图不写入本地文件或数据库。网络请求期间存在于内存；`store:false` 控制 Responses 保存行为，不等于供应商承诺零保留。

接口依据：

- https://developers.openai.com/api/docs/guides/structured-outputs
- https://developers.openai.com/api/docs/guides/images-vision

## 手机浏览器测试

默认只允许本机连接。若要在同一可信 Wi-Fi 的手机上测试，先停止原服务，在 PowerShell 设置：

```powershell
$env:LENS_HOST = '0.0.0.0'
$env:LENS_ACCESS_TOKEN = '替换成自己设置的长随机口令'
npm.cmd start
```

在手机打开 `http://电脑局域网IP:4317` 并输入口令。Windows 防火墙是否允许连接取决于本机配置，项目不会自动更改防火墙。HTTP 局域网模式用于合成或脱敏测试数据；这不是公网部署。模型设置只能在服务所在电脑修改。移动端剪贴板受浏览器安全上下文限制时，会选中文本供手动复制。

## 已实现与限制

| 能力 | 当前状态 |
|---|---|
| 聊天、人物、关系、证据、分析和反馈持久化 | 已实现，SQLite |
| 6+2 本地体验 | 六个模板化规则视角、首席策略和独立规则终审；只验证流程 |
| 6+2 模型分析 | 接口和失败处理已实现；无实际密钥时只完成模拟接口测试 |
| 贝叶斯 | 单次情境假设实验，先验 0.5、规则似然比 1.8，后验约 0.643；未校准，不作人物标签 |
| Outcome 学习 | 反馈进入下一轮 GPT 上下文；同关系/目标/情境的 Beta(1,1) 正负反馈实验统计，UNKNOWN/MIXED 不更新；本地规则不自动优化候选 |
| 多轮自动积累信念 | 尚未实现；重复输入不会重复加权 |
| 人物/关系隔离 | Streamer/Person/Pair 已拆表；六个配置位的记忆/反馈按关系检索；仍为单人管理，不是多租户登录鉴权 |
| iPhone/Android 浏览器 | 响应式界面；真机结果需要分别登记 |
| Android 输入法、单帧授权、跨 App 确认插入 | v0.14 工程预览，含稳定性和选图回归；真实 GPT/OCR 和三平台真机待验 |
| iOS 主 App、照片入口与建议键盘 | 云端构建/核心与界面测试已通过；真机签名与平台待验；分享扩展未实现 |
| 导出与删除 | JSON 导出、人物级级联删除及回执 |
| 自动保留期、备份清理、磁盘加密 | 尚未实现；数据存至用户删除，依赖本机磁盘权限 |

本轮 Goal 是可操作测试版。关于所有主流手机、原生键盘、实时读屏的产品目标仍在项目基线中，不能用网页适配替代其验收。

记忆可改为争议/过期，假设可反证/撤销；下一轮不把它们当已确认事实，旧缓存失效。Outcome 修订作为追加事件保存，当前统计用最近修订；不自动抹去历史分析中的引用。人物级删除会删除**所有主播**与该人物的关系、反馈和修订事件。已导出的文件及备份不会自动删除。

历史检索最多 8 条可用记忆、8 条纠正记忆、12 条人工审核假设、5 条反馈；反馈统计最多查看 200 条记录，展示至多 8 组策略。上下文预算为 24,000 字符（不是 token），超出时裁掉低优先级记录并在回执记数量；当前原文另限 20,000 字符。每条分析有上下文修订/ID 回执，不保存第二份完整上下文快照。

## 升级与备份

已有数据库首次升级会做事务式增量迁移：旧档案背景、记忆和分析只绑定到主播 0001，其他主播无自动私聊共享。建议升级前运行 `npm.cmd run backup`，使用 SQLite 原生备份 API 生成 `runtime/backups/` 下唯一文件，不覆盖现有备份。本次升级已经备份并核对原有五类记录数量不变。

恢复时先停止服务，保留当前数据库，再从所需备份恢复；不要在运行中直接覆盖数据库。备份包含私人数据，需自行保护和清理。

## 代码结构与验证

```text
app/server.mjs       本地 HTTP API、输入校验、CSRF、可选局域网口令
app/store.mjs        SQLite 表、事务、去重、关联删除
app/engine.mjs       规则分析、模型契约、独立终审、贝叶斯公式
app/context.mjs      最小上下文、行为观察、反馈统计、保守表达规划
app/backup.mjs       原生 SQLite 一致性备份
app/public/          原创中文响应式界面
app/tests/           核心逻辑及真实 HTTP 接口测试
runtime/lens.sqlite  本机运行数据（不提交）
```

执行 `npm.cmd test`。最新范围和限制见 [v0.14 验收报告](../07_reviews/V0_14_ACCEPTANCE.md)，合成文本及真实 GPT/OCR 测量入口见 [evals/README.md](evals/README.md)。
