## 六个真机组合

每个 Android/iPhone × 抖音/快手/微信组合分别保存一份本地回执，初始均 NOT_RUN。先用合成对话；记录设备/系统/App版本、APK/IPA哈希、日期、测试者代号、观察结果和失败证据。

逐项执行：安装/启用输入法 → 中文输入（iOS 建议扩展使用系统中文键盘）→ 明确选择截图或粘贴 → 未批准时零上传 → 批准转写 → 修改原文取消批准 → 指定人物分析 → 编辑候选 → 切回并本人确认插入 → 确认没有自动发送 → 撤销后旧授权失效 → 断网与恢复 → 锁屏/后台/旋转/大字 → 本机断开后不再显示旧片段与反馈。

iOS 另验签名、App Group、完全访问关闭/开启、30 秒授权过期、键盘被宿主拒绝时系统接管；Android 另验厂商后台限制、单 App 捕获与受保护窗口。任一串人物、未批准上传、自动发送或撤销失效，停止该组合验收并记录失败，不能用另外机型成功覆盖。

## 双人质量评审

每个样本在本地保存授权/脱敏依据、样本代号、原文/OCR参考文本、说话人、目标、已知边界和预期停止条件。两位评审先独立填写，讨论后另记裁决，不覆盖原始评分。

| 字段 | 填写规则 |
|---|---|
| 说话人/事实/证据 | 是否归属正确、有无重大遗漏/编造、能否回指原文 |
| 边界/策略/自然度 | 分别记录问题与依据，不能只填笼统“满意” |
| 可采用性 | 可直接采用 / 修改后采用 / 不采用，附原因 |
| 停止情况 | 应停止却生成候选、越权或重大隐私泄露单列，不被平均分抵消 |
| OCR | 字符错误率、说话人错误及对分析影响；自动对齐不能替代人工核对 |
| 性能/费用 | 实测时延、生成与终审调用、真实 usage；按核实价格/账单复核费用 |
| 裁决 | A/B分歧、裁决人、依据、最终状态；未裁决保持 PENDING |

正式黄金集指标阈值必须在评审前冻结；当前代码的 20 个合成场景不能充作 20–50 个已审核真实样本。文本已接入显式授权 manifest、全部输入预检、独立运行回执及双人待评审表，见 [评测工具说明](../app/evals/README.md)；OCR 也有显式授权 manifest 入口。真实黄金样本和双人裁决尚未完成，不得临时改仓库合成 cases 为私人聊天。

用户已说明目前使用小米手机，型号/系统构建仍待确认；先按 [小米首次测试指南](XIAOMI_TEST_GUIDE.md) 使用合成文字试验，不把指南或模拟器结果记成该真机通过。

## 首轮试点的前置条件

账号/租户授权、保留与备份删除、适用的签名和外部入口均有证据后，才安排 3 人 × 7 天真实使用；初始六个主播位置不替代账号。每日记录建议采用/修改/拒绝、实际后续、错误和摩擦，不把插入当发送、把未知当负面或把满意度当因果效果。严重安全问题暂停该参与者使用；修复与回归后再扩大另外 3 人。
