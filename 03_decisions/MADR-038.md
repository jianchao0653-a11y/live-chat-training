# MADR-038：移动敏感状态清理、有界读取和原生专用监听器

- 日期：2026-09-08
- 状态：ACCEPTED FOR IMPLEMENTATION，运行验收见 v0.15.1 回执。
- 授权：用户“按计划开展”。
- depends_on：MADR-032–037。
- supersedes：MADR-037 将代理标记拒绝作为唯一服务内防护的实现；停止共享口令式局域网管理网页。保持本机单人管理与发布 NOT_READY。

## 决策

1. Android 断开本机连接时清除片段、草稿、配对码、人物列表、反馈引用和配置恢复对象；重建只含未连接状态的 Activity，断开状态不进入横竖屏恢复对象。服务端撤销仍由电脑控制，不把本机清理伪装成远端撤销。
2. iOS HTTP 使用异步字节流，有已知长度时提前拒绝超限，没有长度或长度不可信时按实际读取字节限制，超限由 Session 取消；文件用 FileHandle 分块有界读取，写入同样检查大小。保持响应小于 2 MB、共享文件小于 64 KB，保留 TLS/重定向限制/文件保护。此方案限制本应用累计读取，不声称控制操作系统所有缓冲或完成真机 OOM 验收。
3. 同一服务进程创建本机管理端口 4317 与原生专用端口 4318。专用监听器在任何路由处理前拒绝非 `/api/native/`，与主工作区共享授权 Map 和资源预算。HTTPS 只能转发 4318；主工作区只允许 loopback，不再允许 LAN 共享口令管理。

## 取舍与验收

不从 Forwarded/Host 推导本机管理权限；一个刻意改写且没有标记的代理与本机进程不可辨识，故采用不同监听入口的能力限制。部署到错误管理端口仍有风险，实际 TLS/域名/upstream 外部验收未完成。多账户登录权限须独立实现。

补充 Node 实际 HTTP 代理与配对/撤销回归，Swift 按需生成大流、长度前置拒绝和文件边界测试，Android 断开后旋转 UI 回归。修复使用 v0.15.1 / build16 标识，不覆盖 v0.15.0 移动包的历史证据。UI 颜色/布局规范沿用 MADR-036。
