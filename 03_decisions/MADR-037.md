## 问题与决策

OCR 原来没有并发准入，已配对设备可以并行消耗模型费用。网页与全部设备现在共享最多 2 个付费工作流；每个滚动 60 秒最多准入 30 个预留调用单位，分析一次预留 2 个（生成＋独立终审），OCR 预留 1 个。超限直接 429，不排队、不自动重试。异常释放并发槽，但不返还分钟预算；缓存与本地规则不占付费预算。

这是单进程流量保护，计量的是工作流开始时的保守预留，不是精确账单、实际调用时间窗或日/月费用封顶。服务重启会清空记录。多实例、公平配额和按账户费用上限须在认证租户阶段实现。

恢复校验使用当前程序在内存新建的 SQLite schema 作严格模板，比较 user_version 与全部应用 schema 对象（包含约束、索引，拒绝增加的触发器/视图），再执行完整性和外键检查。仅验证当前版本原样结构；等价但不同 SQL 定义、旧版本和未来版本均拒绝，需专用迁移流程。源文件只读，复制目标仍须全新，绝不自动激活。此检查不证明备份来源、业务数据正确性或加密完整性。

管理 API 对 Forwarded、X-Real-IP、X-Forwarded-* 标记一律拒绝，不从这些标记推断本机权限。原生 API 保留自己的配对/设备/短期授权校验。由于无标记且改写 Host 的代理无法被当前服务识别，部署必须只转发 `/api/native/`，不能将整个本机工作区公开。

模型输出 schema 检查使用 own-property 判断未知字段，拒绝 `constructor`、`toString`、`__proto__` 等原型继承名。没有证据表明此前会修改 JavaScript 原型或导致代码执行。

## 取舍与验收

不采用客户端按钮禁用作为服务端资源保护；暂不引入分布式队列或重做账户架构。原型保守限额可能使多个合法设备互相等待，这是当前单人管理架构的明确取舍。
