# MADR-045：审核修复中的数据生命周期、准入与恢复契约

- 日期：2026-09-09
- 状态：ACCEPTED / IMPLEMENTED（v0.17.1，发布质量仍未放行）
- 背景：用户要求复核并修复 `output/audit-20260909/REPORT.md`。保留原报告，修复证据另存 `output/audit-fixes-20260909/`。

## 决策

1. 保留期按记录清理。近期独立分析和反馈保留；引用已删除观察的结果按 context receipt 失效，保留该条输入和独立反馈，禁止继续插入旧候选。恢复与日常维护使用同一清理函数，清除孤立事件，并移除历史反馈事件中重复的正文。
2. 相同规范化反馈重试无副作用。真正修订时依赖失效、事件更新和保存放在同一 SQLite 事务；嵌套保存使用 SAVEPOINT。身份库删除账本先写，跨库失败时宁可恢复时保守删除，也不复活已修订资料。
3. 服务与离线维护共用 SQLite EXCLUSIVE 锁，依赖操作系统在进程退出时释放。兼容旧 PID 文件锁：存活或无法验证则拒绝；确认进程不存在才回收。锁数据库不删除；持锁期间保留旧版可识别的 PID 标记，正常释放才删除。
4. 备份清理独立于备份成功。PC 服务启动及每小时执行；备份函数在校验密钥、获取服务锁之前也清理。只处理既定命名的普通文件，不跟随符号链接。7天是保留期，正常调度有最多一小时粒度；关机不能执行任务，恢复后清理。手机说明与实际机制一致，不承诺停机期间物理删除。
5. 忙碌、字段、输入现场先准入，再预留预算和改变现场。已确认零调用且零费用的失败允许再次尝试；可能已计费的失败必须显式确认后用新请求重试，保留旧费用与预留，新请求仍受日/月预算限制。DONE 去重不变。
6. 恢复只接受精确已知 v1 或当前 v2 schema，仍检查完整性和外键。仅在新目标副本迁移，再校验；不改原始备份，不放宽额外触发器等拒绝规则。失败云端恢复保留隔离标记。
7. 手机可查看精简策略、风险与原话依据。插入稿只短暂保留在进程内，实际反馈时可校正并提交；退出账号、断开、切换账号及成功提交时清除。插入不等于已发送。沿用现有视觉和防录屏保护。
8. 请求及维护失败记录随机问题编号、阶段、HTTP 状态、白名单错误码；不记录异常正文、堆栈、聊天、URL、凭据。手机显示问题编号供核对。

## 检索与适用性（遵循 MADR-042）

- 已阅读 [SQLite locking v3](https://www.sqlite.org/lockingv3.html)：OS 文件锁与 EXCLUSIVE 状态、异常退出后的锁释放适用于本机 SQLite 文件，不能外推为跨网络文件系统的分布式锁。
- 已阅读 [Node SQLite API](https://nodejs.org/api/sqlite.html)：Node 24 DatabaseSync 与 timeout 配置；本项目 timeout=0，另一服务存在时立即拒绝。
- 访问日期：2026-09-09。采用系统锁而非无条件删除残留文件；子进程直接退出再启动和活进程互斥均已实测。
- Android 调试包覆盖正式签名包出现 INSTALL_FAILED_UPDATE_INCOMPATIBLE，原因是上一轮模拟器安装正式包、当前使用调试签名，属于既有签名约束。仅清除项目模拟器合成应用后继续调试验收；随后正式 v0.17.0→v0.17.1 同证书覆盖安装成功。未操作个人手机。
- PowerShell 合并 stderr 的原生编译警告使外层返回1；Gradle 明确 BUILD SUCCESSFUL，后续独立签名校验、16 KB zipalign、安装及启动通过。保留原始日志，不以外层退出码假装构建失败或测试全通过。
