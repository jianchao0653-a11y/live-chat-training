# MADR-036：固定移动端视觉系统，按证据优化 UI

- 日期：2026-09-07
- 状态：Accepted；实现与验证进度见 v0.15 验收。
- 决策者：用户确认「按你的推荐来」——清爽浅色＋低饱和绿。

## Context

Android 键盘、安装页、建议页和 iPhone 扩展原先依赖默认控件和零散颜色，缺少明确层级。逐页调整颜色容易反复返工；功能授权链已经有通过的 v0.14 基线，视觉调整需要独立追踪。

## Drivers / Options

需要熟悉的输入体验、稳定的可读性、低维护成本、跨端一致，同时保留平台习惯与敏感片段保护。比较：继续默认控件；引入完整皮肤框架和多主题；建立轻量原生设计 token。选择第三项。前者一致性不足，皮肤框架扩大依赖和回归范围，现阶段收益有限。

## Decision

采用 [移动端视觉规范 1.0](../02_product/MOBILE_UI_SYSTEM.md)：中性浅底、白色表面、低饱和绿强调，70/25/5 作为视觉权重目标。Android LensStyle 与 iOS LensTheme 统一颜色、组件和层级；键盘紧凑工具栏、明确候选区，建议页固定三个工作分区。采用 v0.15 新包名输出与 versionCode 15，保留 v0.14 包和云端证据。

不修改人工批准、敏感输入隔离、图片零自动上传、短授权、手动发送与 6+2 独立终审策略。iOS 继续为建议扩展，完整拼音输入不是本次 UI 所能补齐的功能。

## Consequences / Validation

共同 token 降低维护成本，单一浅色主题减少组合数；代价是尚无深色主题。十列键盘窄屏触摸宽度存在物理约束，记录为高密度例外并保留整键触摸区域。Android 建议页维持 FLAG_SECURE，不能以关闭保护换取截图。

文字对比计算、实际键盘截图、批准/插入/分页/密码/切换/旋转/大字号/离线/选图回归和云端矩阵分别记录。所有已验证声明绑定版本/哈希，v0.14 通过不替代 v0.15 回归。只因可复现体验问题、无障碍缺陷或明确需求变化改版，禁止零散改色。
